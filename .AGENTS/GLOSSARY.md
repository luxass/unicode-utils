# Glossary

Terms and concepts used in the UCD.js codebase and documentation.

## UCD Concepts

### UCD

Unicode Character Database. The collection of plain-text `.txt` files published by the Unicode Consortium that define character properties, names, scripts, blocks, and more. This project parses those files.

### Heading / Header

The region at the top of a UCD file before any data. Contains the file name, version, date, copyright, and description. In AST terms, the heading is everything before the first `SectionNode` that contains a `DataNode`. Extracted by `inferHeaderFromAst()` in `packages/parser/src/header.ts`.

### Boundary

A visual separator line in a UCD file, like `# ================================================`. Represented as `BoundaryNode` in the AST with a `style` property (`"="`, `"-"`, or `"#"`). Boundaries delimit sections.

### SectionNode

A container grouping lines between consecutive boundary markers. Sections contain `DataNode`, `MissingAnnotationNode`, `CommentNode`, `EmptyNode`, and `UnknownNode`. Sections cannot nest.

### DataNode

A semicolon-delimited line carrying property assignments for code points. Contains parsed `codepoint` (as `[start, end]` tuple), `fields` array, and optional inline `comment`. Only appears inside sections.

### MissingAnnotation

A `# @missing:` line in a UCD file that declares the default property value for codepoints not otherwise listed. Formally defined in TR44 §4.2.9. Represented as `MissingAnnotationNode` in the AST (inside sections only). Before any boundary, `@missing` lines are parsed as `CommentNode`.

### EOF Marker

The literal line `# EOF` that appears at the end of some UCD files. Detected by `isEOFMarker()` in `line-helpers.ts`.

### `.comments.txt` files

Expected header text files stored alongside UCD fixtures in `ucd-files/`. Generated by `scripts/generate-header-tests.ts` via `inferHeaderFromAst()`. Used as ground truth in auto-generated header tests — must be manually reviewed when first created.

## API Classes

### RawDataFile

Class in `packages/parser/src/raw-data-file.ts`. Holds the raw content string and a parsed `RootNode`. Can be constructed from a content string or fetched from a URL via `RawDataFile.from()`. Use this when you need to work directly with the AST — inspect nodes, mutate the tree, or stringify back to text. Provides `toDataFile()` to convert to an immutable view.

### DataFile

Immutable frozen wrapper in `packages/parser/src/data-file.ts`. Created via `rawDataFile.toDataFile()`. Holds a frozen `RootNode`. Use this when you only need a safe, read-only view of the parsed AST to pass around without risk of mutation.

### InferredHeader

Return type of `inferHeaderFromAst()`. Contains `fileName`, `version`, `date`, `copyright`, `startLine`, `endLine`, and `text` (the exact raw heading text).

## Functions

### `inferHeaderFromAst(root)`

Extracts heading metadata from a `RootNode`. Walks the AST using the visitor pattern, collecting all nodes before the first section containing data. Returns an `InferredHeader`.

### `visit(node, visitor)`

Depth-first AST traversal. The `Visitor` interface has optional callbacks for each node type. Container nodes fire their callback before children are visited.
